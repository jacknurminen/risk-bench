# V3 experiment boundary

Experiment version 3 starts a fresh dataset under `data/v3/`. The `v2` Git tag
and `data/v2/` retain the earlier application and observations. V3 requires
execution checkpoints; it never reconstructs missing gameplay state from an
older action log. Use a separate v2 checkout to inspect or continue v2 games.

## Execution and failures

A committed transition includes engine and deck RNG state, player state,
pending responses, operation position, notes and prompt context. Provider
errors pause immediately. Invalid decisions receive a bounded correction
exchange and then pause; the correction history survives restoration.
Negotiation requires valid messages or an explicit pass. Empty or malformed
notes pause rather than silently keeping stale memory. Resume retries the
pending operation. No model failure substitutes a random action.

Successful response fragments share a decision ID across their private text,
delivered messages, actions and API trace. Chronological trace position and
decision identity distinguish prior, same-decision and later private evidence.
Human interventions have explicit action provenance. A re-decision receives
a new identity; fork ancestry identifies inherited observations.

## Research pipeline

The canonical instrument is `docs/codebook-v2.md`, copied from the revised
thesis codebook and identified by its version and SHA-256 hash in every
evaluation header. Instrument version 2 belongs to experiment version 3.

Each coder independently screens every delivered message by turn, then
adjudicates agreements, actor-specific obligations and split message claims
over the supplied trace. Screening sees history only through the last message
in its requested turn, without final standings. Its response schema restricts
span IDs and row count to that batch. A mismatched batch gets one correction
attempt; omitted or repeated rows remain missing if correction fails.
Adjudication uses the full observed trace. Neither pass sees another coder's results.
Oversized or malformed responses and provider
failures produce explicit missing coverage or failed/partial member status.
Rerun evaluation to retry; the previous run remains separately reviewable.

The reader calls actor-specific episodes "commitments" and groups proposal
histories under "Proposals & agreements", including rejected offers. Internal
IDs such as `A_NA1` identify records within a coder's run, not codebook codes.
Compact rows show outcomes and expand into terms, evidence and review controls.
Screening diagnostics are grouped separately from message coverage; an ignored
out-of-batch row is not an API failure or evidence of an unscreened message.

Evidence checks validate source spans, exact quotations, actor identities,
links, observation windows, supported outcome sources and temporal ordering.
Invalid units remain visible with reasons and are excluded from descriptive
counts. These checks cannot establish whether a coder interpreted a promise,
scope or intention correctly; substantive assessment still requires review.

Evaluation headers bind the game identity and trace prefix hash. Resuming a
game leaves previous assessments at their original cutoff. Changed source
content or a sidecar copied to another game invalidates its research units.
Human reviews are keyed by evaluator, unit type and unit ID within a run.
Reviews do not alter automated counts.

Counts and adherence denominators are reported per coder. Shared source
anchors expose different episode splits without pretending they are adjudicated
agreement statistics. There is no pooled vote count or aggregate honesty score.
Forks inherit observations, so cross-game analysis must account for ancestry.

Deterministic players exercise uninterrupted versus restored execution,
historical forks and failed calls at decision, negotiation and noting stages.
Scripted coders test evidence rules and pipeline failures without paid API calls.
A substantive pilot on real games is still needed before using the instrument
for thesis conclusions.
